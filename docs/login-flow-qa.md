# 1.9.0 登录衔接验收记录

日期：2026-11-10。所有测试使用独立 Chromium 配置、合成网站及公开 RFC TOTP 测试密钥，不访问真实账号或实际网站验证码。使用项目现有 Playwright 测试环境验证内容脚本、后台消息及渲染界面。

## 已验证的行为

| 场景 | 预期 |
| --- | --- |
| 网页入口、活动标签页填表、管理页打开登录 | 一致遵守全局自动点击开关；关闭时填写但不提交 |
| 普通登录、图片验证码登录、分步登录 | 每次明确操作只提交一次；等待按钮启用时不重复点击 |
| 识别失败、首选结果被拒绝 | 可编辑答案并按 Enter 继续；关闭或修改账号后取消继续操作 |
| 锁库、页面变化、图片刷新、用户自行提交 | 不继续填旧内容或重复提交 |
| TOTP 网站未开启、多组关联或验证码字段有歧义 | 不自动填写 |
| TOTP 动态出现、页面跳转、分格输入 | 确认同源、唯一关联及有效会话后填写一次 |
| 即将过期 | 等下一时间周期后生成，不沿用旧码 |
| 后台重启、再次刷新 | 未消费任务可继续，已消费任务不重复填写 |
| 短信、邮件、恢复码、跨源页面或已有内容 | 保留手动处理，不覆盖 |
| 完整备份 | TOTP 密钥、关联和网站开关一同加密恢复；网站开关属于站点规则配置组 |

112 项单元测试通过；登录、验证码、区域检测、扩展功能、证书等待及完整备份共 136 项浏览器回归全部通过。

最终补充 iframe 锁库撤销处理后重新构建并打包，再运行登录衔接、验证码登录和原有账号安全功能共 59 项浏览器测试，全部通过。两轮共覆盖 147 个不同浏览器用例，包括同源 iframe 的正向填写、多框歧义和锁定后拒绝旧探测结果。最终 ZIP 对应第二轮验证构建。

首轮新流程测试发现：登录跳转会触发旧自动保存逻辑，将账号网址改成 2FA 目标页。已修复为保留登录表单原始网址，并增加回归断言。测试中另修正了两处初始化／断言问题：设置修改需同时写入加密存储和缓存；受控开关的状态需等待异步保存。失败记录保留在临时测试输出中，没有使用自动重试隐藏失败。

已检查“继续登录”紧凑面板与账号详情 TOTP 开关截图；继续按钮与结果在同一行，支持回车，来源地址可换行。实际网站仍可能使用无法识别的自定义字段、跨源认证或多个验证选项；这些情况保留手动入口，不宣称兼容所有网站。
