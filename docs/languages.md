# 界面语言

在 **设置与帮助 → 一般 → 偏好设置 → 界面语言 / Language** 选择语言，点击“应用语言”。锁定页和首次创建页也提供 Language 入口。

- 简体中文：保留现有默认设置。
- English：弹窗、密码库、设置、2FA、备份、提醒及主要网页内操作。
- 繁體中文：同一套界面文案的繁体版本。
- 日本語、Español：常用导航、按钮、表单、验证码及提醒操作；尚未翻译的高级说明使用英文，设置页明确提示这一范围。
- 跟随浏览器：按浏览器首选语言列表匹配。支持中文地区变体、英语、日语和西班牙语；没有匹配时使用英文。

应用后重新载入当前设置页。其他已打开的插件页和网站需重新打开或刷新，避免强制打断正在编辑的内容。浏览器扩展管理页和快捷键页的名称、说明由 Chrome 的界面语言决定，与插件内手动选择独立。

语言偏好随完整加密备份保存；合并备份时选择“插件偏好与安全设置”才会恢复它。另在本机保存一个不含敏感信息的语言代码，让锁定页也能显示所选语言。在锁定页修改语言后，下次解锁会写入加密设置。

保存的账号名称、用户名、密码、笔记、文件夹及资料字段内容保持原样。日期显示和排序使用所选界面语言；不改变原始时间、网页匹配规则或提醒日期的解析范围。网站返回信息和已有诊断记录可能保留原文。

## 维护翻译

文案在 `src/locales/*.json`，以原始中文为键。界面通过 `t(source, values)` 显式选择文案；`{0}`、`{1}` 等参数只替换一次，参数内容不会继续翻译或解析为 HTML。不要对网页 DOM、用户数据或识别用的正则、别名、存储标记做整体翻译。

`tools/locale-assets.ts` 把语言包合并为一个本地静态资源，复用字典键以控制 ZIP 大小。页面初始化时读取语言包，再加载 React 界面，避免模块级标签先固定成错误语言。网页脚本从扩展后台取得所需的文案子集，不增加外部请求、主机权限或可供网站访问的资源。

繁体初稿用开发依赖 OpenCC 转换并保存为静态 JSON。OpenCC 不进入插件运行包；日语和西班牙语可以逐项补齐，未提供的条目回退英文。修改翻译后运行 `npm test`，其中检查英文覆盖和参数一致性；浏览器回归检查切换、锁定、备份、用户内容不变和窄窗口布局。

安装包继续执行 10,000,000 字节上限。打包时用 Node 原生 DEFLATE 压缩，并对 ZIP 中每个文件解压后逐字节校验，安装内容和 OCR 模型不会因压缩方式改变。
