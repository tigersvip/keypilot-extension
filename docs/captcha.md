# 本地图形验证码识别（1.9.0 实验功能）

## 1.9.0 登录衔接更新

所有登录入口统一遵循全局自动点击开关，普通登录和验证码登录均只提交一次，不根据页面仍显示表单而反复点击。账号密码或页面状态变化、锁定、关闭设置等会中断等待。

一键登录识别失败后，面板直接显示可编辑输入框；填写答案后点击“继续登录”或按 Enter，即可填写并提交。自动提交被网站拒绝后，可点击“修正验证码”，重新识别或修改结果再继续。操作绑定原账号、表单和最多两分钟有效期；关闭面板、修改账号密码后取消。单独手动打开的识别面板仍只填写，不提交。

TOTP 按网站开启、即将过期等待下一组等能力见[身份验证器说明](authenticator.md)。本版未修改 OCR 模型和识别算法，交互测试通过不表示真实网站识别准确率提升。

在“设置 → 自动填表 → 本地验证码识别（实验功能）”开启。默认关闭；密码库需要保持解锁。更新插件后，请在扩展管理页重新加载扩展，并刷新已经打开的网站。

## 使用方法

**一键登录：**开启本地验证码识别后，点击账号的“一键登录”，插件填写账号密码，自动识别同一表单内唯一明确的图形验证码，把首选字符或算术答案填入网页，并尝试点击登录一次。无需另外选择候选、确认填写或点击登录。已有的验证码输入会保留；只点“填表”不会启动 OCR 或提交。识别失败、图片刷新、修改输入、关闭识别面板、切换标签页、停用功能或锁定时暂停，交由用户处理，不换候选反复提交。首选仍可能读错，不承诺登录成功。短信、邮件、TOTP、滑块及配对不明确的验证项继续停止自动提交。两步登录支持在下一步出现密码和图片验证码后继续。

**单独识别：**

1. 在网站打开含图形验证码的登录表单，点击或聚焦验证码输入框。
2. 点击旁边的“识别验证码”。插件自动判断数字、大小写英文字母、常用 ASCII 符号和简单算术题，不需要选择类型，也不依赖输入框的数字键盘提示判断类型。算术题直接预填计算结果，例如 `8 × 3 = ?` 预填 `24`，同时显示识别到的算式。
3. 无需设置即可识别。固定四位的网站，可展开“网站位数提示（可选）”，选择“已知位数 → 4 位”，再点“记住此网站规则”。以后自动恢复位数；修改后需要重新识别。
4. 首选候选自动进入结果框并高亮选中，不再因为分歧而清空。可直接使用，也可点击其他候选或修改文字；有分歧时保留简短提示。普通字符位数不符合规则时不能填写；算术答案不受字符位数规则限制，支持一位数、零、负数和有限小数，也不修改保存的规则。
5. 点击结果框旁边的“确认填写”，或在结果框按 Enter，随后由你手动点击网站的登录按钮。面板缩小图片预览、移除重复说明，位数提示移到下方折叠区，常用操作无需下拉。
6. 不需要的网站，可展开面板折叠选项，点击“此网站不再提示”。在“设置 → 自动填表 → 已记住的验证码网站规则”清除该网站规则即可恢复；无需关闭全局功能。

网站规则按协议、域名和端口精确区分，不扩展到子域名或其他端口，也不保存页面路径、图片、验证码答案或表单字段。旧规则中的数字／字母限制不再参与识别，已保存的位数继续有效，新规则记录为自动识别；1.8.8 增加可选的单网站关闭状态。可以在面板点击“清除规则”，或在“设置 → 自动填表 → 已记住的验证码网站规则”清除。其他页面修改规则时，当前旧结果会失效。单网站关闭同时在后台禁止读取截图和识别请求，规则保存于加密密码库并随备份恢复。

图片刷新、页面跳转、输入框已经被手动修改时，旧结果不能继续填入，需要重新识别。关闭识别面板、切换标签页、停用功能或锁定密码库会清除当前候选。无结果时可以直接手动输入，不需要关闭插件。

## 支持范围

- 1.8.8 将网页区域判断与 OCR 分开。联合字段名、标签、占位文字、ARIA 关联、图片标记／端点、字段容器和位置判断，不使用站点白名单或只靠距离。支持中文、英文常见提示，以及法语、西班牙语、葡萄牙语、德语、日语、韩语、俄语、阿拉伯语的部分标签写法；这些是页面提示兼容，图像中的可识别字符仍为下述范围。
- 先排除短信、邮件、OTP、搜索、优惠码、订单号、邮编、卡片安全码及可识别的 Logo、头像、二维码。只读取当前字段附近的发送按钮／倒计时，不因表单其他位置有短信验证码而排除真正的图形验证码。“计算结果”不单独作为验证码证据，必须先匹配图形验证区域。多个图片候选分数接近时不显示入口，不单凭最近距离猜图。
- 支持普通表单、动态插入和标签变化、开放的 Shadow DOM 组件，以及已获得注入权限的 HTTP(S) iframe。图片与输入框保持在同一表单、同一文档范围；切换焦点不会把另一个字段的图片拿来填写。观察属性和文本变化并在填写前复查目标；扫描根数、节点数、输入框数和图片数有上限，无循环 OCR 或新增常驻轮询。
- 封闭 Shadow DOM、CSS 背景图、自定义非 input 控件、模糊或缺少标记的图片、过大页面超过扫描上限，以及浏览器禁止注入的页面可能不显示入口；跨域 iframe 中不能读取的图片沿用手动输入，不扩大截图权限。保守判断可能漏掉有效验证码，不能声称适配全部网站或零误判。
- 自动计算两个整数的加、减、乘、除，识别 `+ - × ÷ * /`、带等号或问号的 `x` 乘号、全角数字和运算符。每个整数最多四位；只计算模型实际读出的完整算式，不使用 `eval`，不从残缺字符猜题。除法仅接受最多六位小数内可精确表示的结果，不自行约定四舍五入；除零、连算、括号优先级、未知数求解、中文数字和小数操作数需手动处理。普通字母图片不能仅凭受限的算术模型输出被判作算术题；裸 `3x7` 需要字段算术提示或明确题目标记。
- 1.8.7 算术识别共享原始图像编码器，增加一个 17 类 uint8 输出层。用 2,000 张本地合成算式训练，不改变原 ASCII 及字母／数字复核权重。发现算式后最多追加两个图片视图，保留除号小点，结合完整读数判断运算符；计算结果默认选中，单个答案不再显示重复候选按钮。
- 1.8.7 普通字符复用已计算的复核视图：多个视图读出一致的完整高分字符串时，可纠正原首选漏字。不为此增加图片识别次数，不根据期望长度补字，继续保护符号与稳定的原始结果。
- 2–10 位数字、大小写英文字母与常用 ASCII 符号，保留前导零与大小写。验证码模型识别整行，轻量英文模型复核大小写和符号，数字模板提供额外证据。逐字复核保留原始相对高度、基线及短符号；不会根据用户未填写的位数提示硬凑四位。1.8.4 保留各字符的分数，只比较有分歧的位置，避免整串平均分掩盖单个低分字符。跨引擎的一致读数优先于同一文字模型的重复猜测；候选截断之前保留与验证码模型兼容的完整读数。只在实际读到的完整候选之间排序，不把 `O` 直接改写成 `0`；存在分歧仍需核对。
- 基础读数不一致时，最多额外执行一次调整字符间距的整行复核。保留相对字高、基线和标点小点，改善间隔过大导致的误分割；不会循环重试，不新增模型或远程请求。
- 1.8.5 对难图增加有界的整串 CTC 候选搜索。通过累计空白和重复字符的路径保留可能被漏读的字符，不硬拆粘连字形，也不强制凑成四位；只有模型实际观察到的序列能进入候选。相对序列分数不是正确率。
- 原始读数把握不足或字符可能粘连时，最多追加两个掩膜视图、一个横向拉伸视图和两个连续灰度视图。连续灰度保留抗锯齿笔画，轻度中值处理减少细线；不直接把所有非黑色像素删掉。颜色分离、清理与裁边均只用于复核，保留原图；清理会丢失大量笔画时放弃该掩膜。不得因区域粘连而把完整字符串缩短，候选长度不符合网站提示时仍不能填写。额外识别失败会保留原结果并释放引擎，下一次可重新初始化。
- 1.8.6 新增小型字母／数字复核输出层，与原模型共享图像编码器，不运行第二套大型模型。使用本地生成的 3,000 张图训练这一层，原始编码器及 ASCII 输出权重不变；训练库不进入安装包。高分且完整的复核读数可以调整首选，保留原候选；不覆盖已有符号结果、较长的完整结果或有强文字证据支持的原始字形。两个输出层共享特征，不能当作两个独立引擎的一致投票。
- 清理后的完整高分文字读数可以复核大小写；两个逐字对齐的可靠读数与原模型序列路径共同支持时，可以纠正粘连造成的漏字。仅使用图片实际读出的候选，不凭规则补字。
- 从字段名称、标签、占位文字判断图形验证码，再寻找附近的图片或 Canvas；不明确的表单可能不显示入口。
- 优先直接读取已经加载的图片。跨域图片无法读取时，仅在当前顶层标签页完整可见的情况下，截取当前显示的像素；不会额外请求验证码网址，避免网站重新生成验证码。
- 可读取的 Canvas 支持识别与填写前复核。被跨域图像污染、无法读取的 Canvas 不使用截图结果，因为无法可靠判断它是否已经重新绘制。
- 跨域图片位于 iframe、图片未完整显示、页面布局变化或尺寸不适合时，可能需要手动输入。多处候选时先聚焦需要填写的输入框。
- 不支持中文、滑块、点选、拼图或行为验证。短信、邮箱验证码与 TOTP 使用各自原有流程。

验证码模型也不是针对所有网站训练的。1.8.7 会尝试文字粘连、重叠、扭曲和密集干扰线，但没有实现可靠覆盖：本轮使用新字体的独立合成组中，多种严重干扰叠加时首选为 0/32。大小写及 `I/l/1`、`O/o/0` 仍可能出错，多个读数也可能得出同一错误答案。单独识别可以核对候选；1.8.9 一键登录直接使用首选尝试一次，需要核对网站返回的结果，不承诺自动登录成功率。

## 本地处理与资源占用

自动识别使用随扩展安装的精简 ddddocr 模型、ONNX Runtime Web 1.31.1、Tesseract.js 7.0.0 便携 LSTM 内核，以及去词典的 tessdata_fast 英文复核模型。数字模板 `ocr/digits-v1.bin.gz`（167,205 字节）保持原版本。原始验证码模型保留 94 个可打印 ASCII 字符及 CTC 空白的输出权重，从 13,606,051 字节降到 5,263,831 字节；这些保留权重没有训练或修改。1.8.7 在已有字母／数字复核层之外追加算术层，模型为 5,346,935 字节，gzip 为 3,728,633 字节，比 1.8.6 仅增加 9,973 字节。英文复核数据约 365 KB，避免把整个英文单词词典带进扩展。

模型和 ONNX WASM 资源以 gzip 保存，调用时在独立 Worker 内解压。资源路径固定为扩展自身资源，不调用云端 API，也不从 CDN 下载代码或模型。单任务最多等待 25 秒，空闲 60 秒后终止识别 Worker、释放模板引用；单线程 ONNX 不要求网页启用跨源隔离。未启用识别时不加载模型。安装文件大小与识别时的内存占用是不同指标，gzip 不会降低推理本身需要的内存。

1.8.9 完整包 9,929,770 字节（9.93 MB），安装文件 13,323,623 字节（13.32 MB），共 94 个文件，包含第三方许可；相较 1.8.8 ZIP 增加 1,773 字节，全部 10 个 OCR 资产与权限保持一致。SHA-256：`7304b58336f175341320b161d173c9202900806bcc3a4fead7c7a8406779c57a`。`npm run package` 构建后校验 ZIP 每个文件与 `dist` 一致，并强制 ZIP ≤ 10,000,000 字节、安装文件 ≤ 15,000,000 字节；超过预算不会写出新包。扩展显示版本与包版本同时校验，并检查 manifest 内容脚本能作为经典脚本执行，避免共享 ESM 导入使网页入口失效。此前 1.8.2 包为 5.21 MB，并未覆盖专用模型的功能。

跨域回退过程中，当前标签页截图仅在内存中暂存，裁剪后仅将验证码区域交给识别引擎。图片、候选和截图不写入密码库、日志或浏览器存储，也不包含在备份中。功能开关随完整加密备份保存；合并备份时选择“插件偏好与安全设置”恢复开关，选择“站点识别规则”恢复验证码网站规则。替换或新安装恢复包含两者。

主要代码见 `src/offscreen/captchaOcr.ts`、`src/offscreen/captchaNeuralWorker.ts`、`src/shared/captchaConsensus.ts`、`src/shared/captchaArithmetic.ts`；来源、改动与许可见安装包 `licenses/ocr-NOTICE.txt`。`tools/ocr/prepare-models.py` 从固定上游哈希裁剪原模型，并用仓库中的 `tools/ocr/review-head.npz` 和 `tools/ocr/math-head.npz` 追加已量化的输出层，需要开发环境安装 Python、NumPy 和 ONNX；本轮重建与分发模型逐字节相同，1.8.6 的已有权重也已逐个核对。正常构建使用已保存的资产，最终用户不需要 Python 或 EXE。模型及检查点 SHA-256、训练设置记录于 `src/ocr-models/metadata.json`。运行库只带单一 WASM 变体，未附带 WebGPU、训练库或其他语言模型。

训练复现仅供开发：`npx tsx tools/ocr/render-head-training.mts --out C:/Temp/keypilot-head-training` 生成带预先标签的图片，再用 `python tools/ocr/train-review-head.py --data C:/Temp/keypilot-head-training --out C:/Temp/review-head.npz` 训练字母／数字层。算术层先用 `npx tsx tools/ocr/benchmark-arithmetic.mts --render-only --out C:/Temp/keypilot-math-training --seed 202611187 --count 500` 生成 2,000 张图，再用 `python tools/ocr/train-review-head.py --arithmetic --data C:/Temp/keypilot-math-training --out C:/Temp/math-head.npz` 训练。需要 PyTorch 2.7.0 CPU、Pillow、ONNX Runtime 和生成器指定的 Windows 字体；字体和数值运行库差异可能改变再训练结果。普通安装、运行及打包均不需要这些库。训练仅更新 1024→63 或 1024→17 的线性输出层，不上传任何用户图片，不使用真实网站验证码作为训练材料。

## 1.8.9 验证范围

测试流程：网页内“一键登录”或密码库打开登录 → 填写账号密码 → 本地识别验证码首选 → 填入网页 → 点击登录一次。测试页为 `https://captcha-login.example.test/login`，由 Playwright 路由到本地合成表单；没有访问或提交用户的真实网站。Browser plugin not available，沿用项目已有 Playwright 与隔离 Chromium。

新增用例覆盖开启／关闭、按网站停用、普通字符与算术、只填表、手动已有答案、并发请求、手动提交、OCR 中修改密码／验证码／图片／关闭／锁定、按钮延迟启用、两步登录、刷新后再次明确登录及内容脚本重复注入。

验证结果：`npm test` 111/111 通过；最终包执行验证码、区域检测、一键登录、常规扩展、证书等待及完整备份共 109 项浏览器回归，其中 108 项通过，1 项手动识别等待超时。该检测套件原先未使用应用的事务锁初始化合成密码库，改为相同事务写入后，检测套件 10/10 通过，超时用例另连续复测 3/3 通过。新增一键登录 21 项在最终包上全部通过。构建、ZIP 完整性及 OCR 资产一致性检查通过；测试记录保留了首次超时，没有以自动重试掩盖结果。
